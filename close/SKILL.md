# close

확정된 사안(이벤트 컨테이너)을 정본화해 봉한다. 개념 권위 = vault `CLAUDE.md`
§회의 생애주기 **Phase B** (2026-06-22 확정) — 이 문서는 그 실행 절차와 가드레일만 담는다.
회의뿐 아니라 "버전이 회람되다 확정되는" 사안 전반(이사회 서면결의·의견서 컨펌 등)에 적용.

## 경계 (기존 스킬과 안 겹침)

- [[brainify]] = 인박스 → PARA *신규 편입* (Phase A 공급, 낙관 배치로 폴더가 쌓임).
- [[backfill]] = 이미 filed 된 사안에 `_thread`·`_parse`·인맥 *소급 보강*.
- **close = 확정 후 수렴·프루닝·정본화** (Phase B). brainify 가 열고, close 가 봉한다.
- **Claude Code 전용.** OpenClaw 이식 금지 — 비가역 삭제 + 대화형 승인 게이트가 본질이라
  자동화 트랙(ro 마운트·텔레그램)과 구조적으로 양립 불가. OpenClaw 의 역할은 (향후) 확정
  신호 감지 → "클로즈할 때가 됐습니다" 넛지까지만.

## 모드 — 앵커형 단건 (`/close <자연어 앵커>`)

앵커 = 날짜·기관·키워드의 느슨한 조합 (예: "7.2 KINS 회의", "작년 10월 이사회 서면결의").
정확한 폴더명 불요 — 해석은 스킬이, 경계 확정은 Dr. Ben 이.

### 1. 앵커 해석 → 클러스터 탐색

- 앵커의 날짜·키워드로 후보 수집 (형제 폴더가 **다른 상위 폴더에 흩어져 있을 수 있음** —
  부서 폴더 안만 보지 말 것. 2026-07 실측: zoom 차기일정 씨앗이 상위 `대한핵의학회/` 에 있었음):
  - **키워드는 기관명 이형(異形)까지 확장** — 약어·한글 전체명·영문명 셋으로 각각 find
    (예: KINS ↔ 한국원자력안전기술원). 캡처 폴더명은 메일 제목에서 오므로 전체명이 흔하다.
    (2026-07-13 실측: `*KINS*` 만 찾다 "한국원자력안전기술원…" 폴더 3개 누락 → 클로즈 후 재정리.)
  - `find sources/0[12]_* -maxdepth 4 -type d -iname "*<키워드>*"` + 날짜 앵커 전후 폴더 `ls`.
    탐색 결과를 `head` 로 절단하지 말 것 — 절단된 목록이 클러스터 멘탈모델로 굳는다.
  - `grep -ril "<키워드>" knowledge/<추정 영역>/` 로 허브·낱개 노트와 wikilink 추적.
  - 노트 frontmatter `gmail_thread_id` 수집 (병합·보존 대상).
  - **★ thread-id 역검색 (생략 불가)**: 수집한 **모든** thread id 로 sources 캡처 폴더를
    역검색해 경계표에 반영 — `grep -l "<tid>" sources/0[12]_*/**/_thread.md`. Phase A raw
    캡처(동반 노트 無·발신자명 폴더)는 키워드·knowledge grep 에 안 걸리므로 이 역검색이
    유일한 안전망. (2026-07-13 실측: 병합 _thread 에 id 5개가 있었는데 역검색 부재로
    그 id 를 담은 폴더 3개를 놓침.)
- 클러스터 구성원 분류: **본건**(회의/결의 그 자체) · **준비**(사전 조율·검토요청·리마인드) ·
  **회람**(회의록/최종본 확정) · **씨앗**(차기 일정 등 선행 이벤트).

### 2. 승인 게이트 ① — 경계 확정 (생략 불가)

포함/제외 목록을 표로 제시하고 Dr. Ben 승인을 받는다:

- **앵커(본건) 폴더** + 표준 컨테이너명 제안 — `YYYY-MM-DD(개최일)_기관_조직_N차회의`
  (개최일 앵커, "회의록" 아닌 "회의"로 끝냄). 그 부서의 기존 사안 명명 형식이 있으면
  **부서 내 한 형식** 우선 (brainify §사안 명명 규약).
  - **상대기관(counterpart)은 사안 슬롯에** — 접두는 항상 자기 `조직_부서`(관점 주체),
    상대는 사안 첫머리로 (예 `2026-07-02_KSNM_방안위_KINS업무협의_1차회의`).
    **공식 회의명이 상대 먼저라도 폴더명은 따라가지 않는다** — 공식 명칭 보존은
    frontmatter `title:`·원본 파일명의 몫. (2026-07-13 KINS 1차 실측: 공식명
    "한국원자력안전기술원 및 대한핵의학회 미팅"을 따라 `KINS-KSNM_` 접두로 지었다가
    부서 내 형식 이탈·`조직_부서_*` 검색 누락 확인 → rename.)
- **포함 제안**: 준비·회람 폴더 목록.
- **경계 확인 필요**: 씨앗 노트(차기 회의로 넘길지 정본 「차기」에 흡수 후 삭제할지),
  소속 모호 폴더. 모호하면 **제외가 기본** — 잘못 포함해 삭제하는 것이 최악.

### 3. 실행 계획 제시 → 승인 게이트 ② — 삭제 목록 (생략 불가)

경계 확정 후, 실행 전에 먼저 **스레드 신선도 재확인**: 클러스터의 각 `gmail_thread_id` 를
`gog gmail thread get` 으로 현재 message_count 와 `_thread.md` frontmatter 대조 — 캡처 후
후속 메일(특히 **내 발신**: sent-poll 재캡처는 00_inbox 범위뿐)이 있으면 병합 대상에 추가.
(2026-07-13 KINS 1차에서 수동으로 한 "마감 후 메일 유무" gog 확인의 제도화. gog 실패는
non-fatal — 보고하고 진행.) 이어서 다음을 **구체 파일 단위**로 제시하고 재승인:

- **평탄화 계획**: 어느 폴더가 컨테이너로 합쳐지는지 (sources + knowledge 짝 동일).
- **프루닝(삭제) 목록**: 중간 버전 파일 각각 — 파일명·왜 중간본인지·최종본이 무엇인지.
  - **가드레일**: ⓐ *Dr. Ben 본인 레드라인*(자기 주석·수정 제안본)은 목록에 넣지 말고
    별도 표시 → 최종본 반영 여부 확인 후 개별 판단 (자동 삭제 금지).
    ⓑ 최종본 판정이 조금이라도 모호하면 삭제 대신 보류 표시.
- **삭제될 낱개 `.md` 목록**: 준비메일 노트·씨앗 노트 등 — 각각 "그 정보가 정본
  어디(§타임라인/차기/캘린더)에 흡수되는지" 명시. 흡수처를 못 대는 노트는 삭제 금지.

### 4. 실행 (승인 ② 후에만)

1. **평탄화** — 컨테이너 폴더(sources)로 하위/형제 폴더의 원본·첨부·`_parse` merge.
   knowledge 짝 경로 동일 적용. 컨테이너명이 기존과 다르면 rename + 참조 동반 갱신.
2. **프루닝** — 승인된 목록 그대로만 삭제. 목록 외 파일은 건드리지 않는다.
3. **`_thread.md` 통합** — 클러스터의 모든 `_thread.md` 를 **시계열 병합한 단일
   `_thread.md`** (raw 층). frontmatter `gmail_thread_ids:` 리스트로 전체 보존.
4. **허브노트 정본화** — `knowledge/.../<컨테이너명>.md` 하나 (파일명 = 폴더명):
   한 줄 요약 → 핵심(결정사항·액션) → 내 생각 → **준비 경위 타임라인**(프루닝된
   중간본·준비메일을 1줄씩 흡수) → 차기(씨앗 흡수분) → `[[관련 노트]]`·`[[인맥]]`.
   frontmatter: 표준 + `sources:`(컨테이너 상대경로) + **`status: closed`** +
   `closed: YYYY-MM-DD`. (향후 `/close audit` 이 이 필드로 open 재고를 질의.)
5. **낱개 노트 청소** — 승인된 `.md` 삭제 (04_archive 의 준비메일 노트 포함, 위치 불문).
6. **참조 리페어** — `grep -rl "\[\[<옛 basename>\]\]" knowledge/` 로 삭제·개명된
   노트를 가리키던 wikilink 를 허브로 repoint. 깨진 링크 0 확인.

### 5. 보고

표로: 컨테이너(최종 경로) · 수렴 N폴더 · 프루닝 M파일 · 보류 K(레드라인 등) ·
thread 병합(thread_id 수) · 삭제 노트 J · repoint L링크 · `status: closed`.

## audit 모드 — 미구현 (의도적)

`/close audit`(클로즈 후보 재고 스캔)은 **사례 2~3건 누적 후** 추가한다. 그때는
휴리스틱 추측이 아니라 `status: open`(또는 status 부재) + 마지막 유입 경과로 질의 가능.

## 제약

- **비가역 삭제 포함** → 게이트 ①·② 는 어떤 경우에도 생략 불가. `--headless`
  모드 없음. cron·brain-drain·OpenClaw 에서 호출 금지.
- **vault = SyncThing** (git 아님, commit 없음). 빠른 삭제→재생성 시 상대 기기 인덱스
  stale 가능 — 대량 이동 후 필요 시 강제 rescan (reference_syncthing_wsl2_stale_index).
- 프루닝은 "원본 불변" 원칙(brainify·backfill)의 **명시적 예외** — Phase B 만, 승인 ② 후만.
- 클로즈 후 그 사안으로 새 메일이 오면(정정·후속) 그건 **새 캡처**(brainify) — 컨테이너를
  다시 열지 않고, 후속이 실질적이면 별도 사안 또는 차기 회의의 Phase A 로.
